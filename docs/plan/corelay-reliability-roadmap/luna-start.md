D:\git\claudecode\corelay-code의 신뢰성 개선을 구현하라.
계획 루트: docs/plan/corelay-reliability-roadmap.

먼저 상위/프로젝트 AGENTS.md와 계획 README.md, spec.md, findings.md, plan.md, contracts.md, validation.md를 읽어라.
git status와 기존 diff를 확인하고 승인된 Chromium 웹수집 변경 및 사용자 변경을 보존하라.
부모 claudecode 저장소와 제품 저장소의 이력을 혼합하지 마라.

현재 plan.md에서 선행 조건을 만족하는 첫 TODO 섹션을 선택하고 해당 sections 작업서를 읽어라.
한 번에 한 하위 단계를 수행하라:
1. 기존 구현/테스트와 호출자를 확인한다.
2. 결함은 실제 production 경로를 사용하는 최소 회귀 테스트로 재현한다.
3. 기존 composition point에서 수정한다.
4. 해당 테스트와 영향 패키지 검사를 수행한다.
5. 섹션에 변경·명령·exit code·미실행 이유를 기록한다.
6. 의존 섹션으로 계속 진행한다.

계획과 코드가 다르면 확인된 코드를 우선하여 근거를 기록하고 계획을 갱신한다.
읽지 않은 함수, 실행하지 않은 테스트, 아직 연결되지 않은 기능을 완료로 보고하지 마라.
임시 성공 응답, mock만 통과하는 구현, 권한 검사 제거, 테스트 삭제로 통과시키지 마라.
스킬은 workflow 지침이며 정책을 상향하지 못한다. full 모드는 명시적 사용자 선택을 실제 executor까지 전달한다.
full에서도 인증·세션 경계·입력 검증·취소·감사·사용자 변경 충돌 검사는 유지한다.

자율 실행 범위는 로컬 구현·테스트·문서 갱신이다. push, release, 배포, 실제 사용자 데이터 삭제는 포함되지 않는다.
기존 사용자 credential로 유료 모델 벤치마크를 임의 실행하지 마라. fake provider와 로컬 fixture를 먼저 사용한다.
외부 서비스가 필요하면 지원 범위·로컬 대체 검증·남은 live 검증을 구분한다.
불확실한 외부 API/라이브러리는 구현 시 공식 문서와 고정 버전으로 확인한다.

컨텍스트가 부족해지면 현재 섹션의 상태·실패 로그 요약·다음 정확한 명령을 저장하라.
이전 세션의 PASS를 근거 없이 재실행하지 말고, 코드가 바뀌었거나 미해결 문제가 있을 때만 재검증한다.
최종 보고는 완료 섹션, 실제 검사, 잔여 문제를 구분한다. 미완료 섹션이 있으면 전체 완료라고 말하지 마라.

## 운영 방식

기본은 섹션 순차 실행이다. 모델 이름만으로 정확성을 보장하지 않으므로 G1/G2/G3에서 독립 검토를 한다.
서브에이전트가 가능하더라도 공유 server.go/loop.go/sessions.go를 동시에 수정하게 하지 않는다.
진행 중 user steering은 기존 목표의 보완으로 기록한다. 범위 변경은 추적표와 의존성을 함께 갱신한다.
