# 실행 순서와 상태 장부

상태: S01~S12 PASS, S13 IN_PROGRESS. Argos 후속 수정(2026-09-20)에서 S13.A의 실제 lifecycle·격리 테스트 acceptance를 보완해 로컬 PASS로 검증했다. 전체 감리는 API·플랫폼 등 미검증 범위 때문에 CONDITIONAL이며 ACP workflow 결합 세션 실행은 미지원이다. hosted OS matrix와 남은 검증 범위는 verify-report.md를 따른다.
우선순위: P0 사용자 데이터/인증, P1 실행 계약, P2 사용성/확장.
루나 기본 실행은 한 번에 한 섹션의 한 하위 단계다. 여러 공유 파일을 동시에 수정하지 않는다.

## 파일 충돌 관리

- server.go: S01/02/03/05/07/08/09/10/11이 접촉한다. 순차 통합. 각 변경은 기존 handler와 별도 책임의 작은 파일로 구성하되 거대한 재구조화 금지.
- loop.go/run_options.go: S02/03/05/06/07/09. 먼저 타입 계약 확정 후 caller 전체를 따라간다.
- sessions.go: S03/04/05/08/09. 버전 migration과 기존 hard-crash tests를 함께 유지.
- tools*.go: 기존 웹 변경과 S02/04/09/11/12 충돌. 시작 diff와 비교.
- Chat.tsx/Team.tsx/tui_commands.go: backend 계약 완료 후 S10에서 UI 통합.
- 스키마나 공통 정책을 바꾸면 직접 의존 섹션만 재검증. 이미 통과한 전 영역 반복 실행은 새 근거가 있을 때만 한다.

## 기록 형식

각 하위 단계 완료 시 해당 섹션에 아래 항목을 추가한다.
- 상태: TODO / IN_PROGRESS / PASS / BLOCKED / NEEDS-REPRO
- 기준 commit 및 이번 변경 파일
- 재현 실패→수정→성공을 보여 주는 test 명령과 exit code
- 미실행 검증과 이유
- 잔여 위험 / 다음 하위 단계
PASS는 테스트 통과에 근거한다. BLOCKED를 PASS로 바꾸거나 검증 범위를 몰래 축소하지 않는다.
자동 commit/push는 이 계획에 포함되지 않는다.

## 검토 게이트

G1: S01~S04 완료 → 인증·정책·세션·데이터 변경 독립 검토.
G2: S05~S10 완료 → 프로젝트 두 개와 재시작을 포함하는 CLI/Web 사용자 흐름 검토.
G3: S11~S13 완료 → capability 차이, 외부 의존 실패, 패키징·호환성 검토.
실행자는 게이트 결과와 수정 근거를 남기고 후속 작업을 이어간다. 심각한 미해결 항목은 의존 섹션만 차단한다.
