# 범위와 설계 계약

## 목표

Corelay를 프로젝트를 바꾸며 장시간 사용하는 코딩 CLI로 만든다.
현재 요청, 프로젝트, 작업, 세션, 실행 권한, 도구 실행, 검증 결과가 일관되게 연결되어야 한다.
전체 권한 모드는 명시적으로 선택 가능해야 한다.

## 범위 구분

- 결함 수정: 설정/인증, 설정 소비 누락, 기존 staged 변경 포함, Undo 충돌, 이미지 미전달, 탐색/압축, UI 연결.
- 기존 기능 연결: 프로젝트·세션·Workstream·TeamPlan, CLI 영속화, 스킬, 권한 상속.
- 확장: 관리되는 CLI 서버 시작, 원격 MCP, LSP, 운영 진단/업데이트.
- 마지막 두 확장은 별도 후반 섹션이며 앞선 결함의 완료를 막지 않는다. 그러나 전체 로드맵 완료를 주장하려면 후반 섹션도 완료하거나 사용자에 의한 명시적 범위 변경을 남긴다.

## 명시적 설계 선택

1. 프로젝트는 정규화된 경로와 안정적인 키로 식별한다. 기존 workspaceStorageKey를 우선 사용한다.
2. 프로젝트 목표·진행의 canonical owner는 기존 Workstream이다. 절차상의 stage는 기존 TeamPlanStage 구조를 유지하고 Workstream 하위의 revisioned Plan에 저장한다. Workstream, Plan, Stage의 ID 공간은 혼합하지 않는다.
3. Session은 project/workspace와 optional workstreamId, planId/revision/stageId 참조를 저장한다. 세 ID의 존재와 소속은 저장/실행 경계에서 검증한다.
4. Run은 Session의 특정 revision, 모델 대상, 권한 정책 snapshot을 갖는다. 실행 중 글로벌 설정 변경은 기존 Run을 바꾸지 않는다.
5. 전체 권한은 OS 실행 계정의 권한까지다. UAC 상승이나 다른 계정 권한을 얻지 않는다.
6. 권한과 인증은 독립이다. 전체 권한이어도 HTTP 인증, 세션 소유권, 입력 계약, 취소, 감사 기록은 유지한다.
7. 기존 저장 파일을 일괄 덮어쓰지 않는다. 버전 필드, 읽기 호환, 검증 후 원자적 저장, 실패 시 원본 보존으로 이행한다.
8. 계획 승인과 전체 권한 선택은 다르다. plan/read-only 모드의 변경 금지는 전체 권한 선택만으로 해제하지 않는다.
9. 스킬은 절차 지침이다. 모델이 스킬 이름을 가짜 tool call로 호출하게 만들지 않는다.
10. 초기 구현 기본 권한은 workspace. 기존 설치를 full로 자동 승격하지 않는다. 서버에 이미 설정된 정책은 migration에서 명시적으로 매핑한다.

## 권한 모드

| 모드 | 파일·실행 | 승인 | 상속 |
|---|---|---|---|
| read-only | 조회 중심, 변경형 도구 금지 | 승인으로 몰래 변경 모드 전환하지 않음 | 하위도 읽기 전용 |
| workspace | 작업공간 변경 허용; 임의 shell은 실질 격리 가능 여부 확인 | 외부 범위/격리 해제는 명시 승인 | 하위는 동일 또는 축소 |
| full | 계정이 접근 가능한 외부 파일·프로세스·네트워크 허용 | 개별 도구 승인 생략 | 명시적 부모 정책 범위 이내 |

workspace는 문자열 검사만으로 OS 격리를 보장한다고 표시하지 않는다.
Windows Job Object만 있는 경우 임의 Bash/PowerShell의 파일·네트워크 격리는 unavailable이다.
그 경우 제한된 도구 경로를 사용하거나, 격리되지 않은 명령 실행 승인을 받는다. 자동 full fallback은 금지한다.
full은 파괴적 명령을 다시 일괄 승인 대상으로 돌려놓지 않는다. 대신 입력 유효성, 세션 경계와 사용자 변경 충돌 검사는 그대로 유지한다.

## 제외

이번 작업에서 다른 제품의 소스를 복사하거나, 사용자 계정의 실제 비밀값을 검사/기록하거나, 원격 배포·push·release를 수행하지 않는다.
가짜 성공, 미실행 검증을 PASS 처리, 통과를 위해 테스트 삭제/권한 검사 우회는 허용하지 않는다.
