## 결정과 범위

- Skills 정책은 전역 기본값 → 등록 프로젝트 override 순서로 해석한다. 프로젝트 경로는 절대·symlink 정규화 후 exact match하며 prefix 유사 경로는 적용하지 않는다.
- B의 loader 순서는 프로젝트 vendor roots(`.claude/skills` → `.codex/skills` → `.agents/skills`) → 프로젝트 `SkillDirs` → 선택된 사용자 홈 vendor root(s) → 전역 `SkillDirs`다. `none`은 모든 root를 비운다. 중복 이름은 대소문자 무시 first-wins를 유지하고, losing copy의 source/namespace/path는 메타데이터에 보존하며 충돌 UI에서 namespaced command를 안내한다. `/api/skills` 응답은 기존 배열 형식을 유지하고 skill 본문은 목록 메타데이터에서 제외한다.
- durable session은 독립적인 skill 정책 snapshot을 저장하지 않는다. S03에서 고정한 Session.Workspace로 해당 프로젝트 정책을 다시 resolve하므로, 프로젝트 정책을 바꾸면 이후 재개에도 새 정책이 적용된다. 별도 session-only override는 현재 설정 계약에 추가하지 않았다.
- 손상된 config를 legacy `config.Load()`가 기본 설정으로 바꾸면 `all` discovery로 열릴 수 있어, RunLoop 정책 경계는 `LoadChecked()`에서 실패를 반환한다. 첫 실행처럼 config 파일이 없는 경우의 기본값은 유지한다.
